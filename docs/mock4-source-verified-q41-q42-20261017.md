## 2. 原稿缺陷 → 源页实际（本批实修）

### Q41

1. **解析 (1) 整段丢字。** 原稿读作「因为存在这样的根结: 左孩子结点的关键字 < 右孩子结点的关键字」，
   漏掉了「**根结点关键字 <**」与「**结点 10**」。源页为：
   「因为存在这样的根结点，**根结点关键字 <** 左孩子结点的关键字 < 右孩子结点的关键字。例如，在题目举例介绍的基数树中，**结点 10** 的左孩子是 100，右孩子是 101（灰色结点），100 > 10，不满足二叉排序树的定义。」
2. **解析 (2) 的 `TreeNode` 定义被 OCR 打坏**（本批明确要求核查 `isEnd`、`lChild/rChild`）：

   | 原稿 | 源页实际 |
   |---|---|
   | `bool isEna; // 标` | `bool isEnd;  // 标记当前结点是否为深色结点` |
   | `string result; // isEna` | `string result; // isEnd == True时，result存储相应的位串的结果` |
   | `TreeNode *1Child，*rChildy` | `TreeNode *lChild, *rChild;` |
   | 收尾 `】` | 收尾 `}` |

   即：变量名是 **`isEnd`**（不是 `isEna`），左孩子指针是 **`lChild`**（字母 l，不是数字 1），
   且左孩子/右孩子在同一行声明（`TreeNode *lChild, *rChild;`）。
3. **解析 (3) 复杂度符号错**：`O(m)` → **$O(n)$**；`O(D` → **$O(n)$**。

## 3. 集合 S 的末项：一处靠「图」纠正「字」的实例

题干原写「给定字符串集合 $S$」，原OCR稿与本轮**早期较低分辨率**读数都把末项认成 `01`。
本轮做了两步：

1. 以 **1200dpi** 定点放大源页该处，末项实为单个 **`0`**；
2. 用图做**独立交叉验证**：源图白结点（= 属于 $S$ 的关键字）为 $\{0, 011, 10, 100, 1011\}$，
   与 $S=\{1011, 10, 011, 100, 0\}$ **逐项一致**；若末项是 `01`，则图中「01」位置应是白结点，
   而图上该位置实为灰结点 —— 与读法矛盾。

故取 `0`。**文字与图互为旁证**，不是单点判读。
