### 6.2 关键负面结论（防止把错答案写进题库）

1. **几何配对策略不可靠 —— 已弃用。**
   `tools/extract_answer_keys.py` 的「同行题号 + 右侧最近字母」配对在 2022 上产出
   36 条**看似完整但错误**的结果：Q9 得 B（实为 D）、Q10 得 D（实为 A）、
   Q37 得 A（实为 B）。**若不核验直接采信，会把错答案批量写进题库。**
   该策略对 2012/2020 恰好正确，说明它**不能跨卷信任**。已从 `build_drafts.py` 移除接入。

2. **区域级 OCR 也不能直接给出 key。**
   RapidOCR 把 `1.` 与 `B` 拆成两个独立检测框，单个框内没有 `N L` 组合，
   整区识别得 0–1/40。逐格裁剪方案亦未能稳定取出字母。

3. **列主序字母 run 版式（2009 型）无法安全自动配对。**
   文本层把字母按列合并成 run（如 `CBAAB` = 第2列 5 个答案读下来，已用源页图证实），
   但各卷 run 数量/长度/坐标漂移不一致（实测 run 数 7/8/9，个别 run 被截断为 3 字符），
   且第 8 列 run 有时出现在页面底部（如 2009 的 `DCDAA` 在 y=419）。
   逐卷调参不具可持续性，**已停止**。

### 6.3 结论与建议

- 旧版 key 的**可靠通路是「源页高分辨率裁图 + 人/视觉逐条读出」**，
  自动方法在本题材的坏文本层上不可信。
- 每卷成本：1 次裁图 + 1 次目视核对（约 40 条）。剩余 10 卷可按此法推进。
- `index/image-verified-keys.json` 已预留结构，补录即可自动生效。
- 41–47 综合题解析（`no-solution` 107 / `thin-solution` 107）本轮未攻，
  仍需先摸清各年答案 PDF 的解析排版。
