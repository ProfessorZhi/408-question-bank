### Q41（表达式树 → 中缀）

设计：中序遍历；叶结点直接输出操作数；非根的非叶结点在左子树前输出 `(`、右子树后输出 `)`；根不加最外层括号。

```c
typedef struct node {
    char data[10];
    struct node *left, *right;
} BTree;

void BtreeToExp(BTree *root, int deep) {
    if (!root) return;
    if (!root->left && !root->right) {   // 叶结点：操作数
        printf("%s", root->data);
        return;
    }
    if (deep > 1) printf("(");           // 子表达式加一层括号
    BtreeToExp(root->left, deep + 1);
    printf("%s", root->data);            // 操作符
    BtreeToExp(root->right, deep + 1);
    if (deep > 1) printf(")");
}

void BtreeToE(BTree *root) { BtreeToExp(root, 1); }
```

实测（`gcc -O0 -Wall -Wextra`，脚本 `scratch/scripts/q41_exprtree.c`）：

```
(a+b)*(c*(-d))
(a*b)+(-(c-d))
```

与题干两例逐字符一致。

### Q42（Prim / MST 唯一性）

```
AB=6, AE=5, AD=4, BC=4, CD=6, CE=5, DE=4
```

### Q43（IEEE 754 单精度复算）

用 Python `struct` 按 float32 逐步模拟 `f1`（32 位回绕）与 `f2`（每步 round-to-nearest-even）：

| n | f1 | f1 机器数 | f2 | f2 机器数 |
|---:|---:|---|---:|---|
| 23 | 16777215 | `0x00FFFFFF` | 16777215.0 | `0x4B7FFFFF` |
| 24 | 33554431 | `0x01FFFFFF` | 33554432.0 | `0x4C000000` |
| 30 | 2147483647 | `0x7FFFFFFF` | 2147483648.0 | `0x4F000000` |
| 31 | −1 | `0xFFFFFFFF` | 4294967296.0 | `0x4F800000` |
| 126 | −1（f1 溢出） | `0xFFFFFFFF` | 2¹²⁷ | `0x7F000000` |
| 127 | −1 | `0xFFFFFFFF` | +∞ | `0x7F800000` |

- `f1(23)=f2(23)=2²⁴−1`，24 位有效位恰好精确。
- `f2(24)` 把 `2²⁵−1` 舍入到 `2²⁵`（偶数尾数），比 `f1(24)` 大 1。
- `f1(31)` 的 32 位全 1 按 `int` 解释为 −1；`f1(n)=f(n)` 的最大 `n=30`。
- `f2(127)=+∞`；不溢出最大 `n=126`；精确最大 `n=23`。

### Q44（机器级代码）

- (1) **CISC**：指令长度不一（push 1B、cmp 3B、shl 2B、ret 1B），含内存操作数。
- (2) `0x0040107F − 0x00401020 + 1 = 0x60 = 96B`。
- (3) `cmp` 做 `i − (n−1)`；`f1(0)` 时 `i=0`、`n−1=0xFFFFFFFF`：
  `0 − 0xFFFFFFFF = 0x00000001`，产生借位，**CF=1**。
- (4) 不能。`shl` 把整个 32 位机器数左移，float 的符号/阶码/尾数字段一起移位，不能实现 ×2；应调整阶码并处理溢出/下溢。

### Q45（二级分页）

- 页内偏移 12 位 ⇒ 页大小 4KB；`0x00401020–0x0040107F` 全在 `0x00401000–0x00401FFF`，**1 页**。
- `0x00401020 >> 22 = 1` ⇒ 页目录号 **1**。
- `(0x00401020 >> 12) & 0x3FF = 1` ⇒ 页表索引 **1**。
- 两者均访问 **第 1 个表项**（编号从 0 开始）。
- scanf：系统调用使 CPU 进内核态；P 等输入 → 阻塞；输入到达 → 中断唤醒 → 就绪；调度 → 运行；返回用户态。

### Q46（信号量）

```c
semaphore mutex_y1 = 1;   // thread1 与 thread3 对 y（读-写）
semaphore mutex_y2 = 1;   // thread2 与 thread3 对 y（读-写）
semaphore mutex_z  = 1;   // thread2 与 thread3 对 z（读-写）

thread1:
    cnum w;
    wait(mutex_y1);
    w = add(x, y);        // 读 x、y
    signal(mutex_y1);
    ...

thread2:
    cnum w;
    wait(mutex_z);
    wait(mutex_y2);
    w = add(y, z);        // 读 y、z
    signal(mutex_y2);
    signal(mutex_z);
    ...

thread3:
    cnum w;
    w.a = 1; w.b = 1;
    wait(mutex_z);
    z = add(z, w);        // 读-改-写 z
    signal(mutex_z);
    wait(mutex_y1);
    wait(mutex_y2);
    y = add(y, w);        // 读-改-写 y
    signal(mutex_y2);
    signal(mutex_y1);
    ...
```

- `x` 仅 thread1 访问，无需信号量。
- thread1 与 thread2 **可同时读 y**（二者都不写 y），因此不用一个全局 y 锁，满足“最大限度并发”。
- 锁序：thread2 先 `z` 后 `y2`；thread3 的 z 临界区只持 `z`，进入 y 临界区前已释放 `z`，随后按 `y1→y2` 获取。不存在“持 z 等 y2”的环，故无死锁。
- **残余说明**：thread3 分两步更新 `z`、`y`，thread2 可能读到“新 z + 旧 y”的组合；本解保证**变量级**互斥（与官方评分表一致），不保证跨变量快照原子性。若要求快照一致，需扩大临界区并降低并发。

### Q47（GBN）

3 位序号 ⇒ 发送窗口最大 `2³−1=7`。

**(1)** `R0,1`、`R1,3`、`R3,3` 的累计确认号为 3 ⇒ 乙已正确收到序号 0、1、2：**3 帧**，`S0,0, S1,0, S2,0`。

**(2)** t1 时基序号 3，已发未确认 3、4；窗口 7 ⇒ 还可发 `7−2=5` 帧。甲未收到乙帧 2，捎带确认号仍为 2：

```

```

**(4)** 捎带确认 ⇒ `Ta=Td`：

```
Td = 1000×8 / 100×10^6 = 8×10^-5 s = 0.08 ms
U  = N·Td / (Td + RTT + Ta)
   = 7×0.08 / (0.08 + 0.96 + 0.08)
   = 0.56 / 1.12
   = 0.50 = 50%
```
