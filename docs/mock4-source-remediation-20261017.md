## 1. P0 修复

### 1.1 Q1：程序段缺失

**原状**：main 稿的程序段是 `Imtuinear 11(m=n）roturnl:else inrmd-mtA2` 这类乱码；源分支稿则整段缺失，
只留一句「源PDF第2页的代码字体不能由当前OCR完整还原，请在程序代码复核完成前参照原卷代码」。
一道问复杂度的题没有代码，等于无法作答。

**取证**：扫描件内嵌图只有 180 ppi，代码字号很小。用 `pdfimages` 抽出原生 1488×2103 图，
裁切代码区后 5–6 倍 LANCZOS 放大读取（600 dpi 渲染只是上采样，未采用）。

**重录结果**：

```c
int fun(int *arr, int m, int n)
    if (m == n)
        return 1;
    else {
        int mid = (m + n) / 2;
        return fun(arr, m, mid) + fun(arr, mid + 1, n);
    }
```

**不猜补的边界（重要）**：

- 函数签名一行的笔画在底本中明显偏淡，`arr`、`m`、`n` 三个参数名无法逐字辨析；
  但正文两处调用 `fun(arr, m, mid)` 与 `fun(arr, mid + 1, n)` 都清晰可读，
  三参数结构由调用点反证，**不是按常见写法臆造**。
- 第 1 行行尾的左花括号在底本中不可辨。代码块末尾却有 `}`。
  **没有替源卷补 `{`**，而是在题下注明「不可辨、未擅自补入」——宁可留一个需要复核的缺口，也不造假。
- 该行仍列入待人工复核项（见 §4）。
